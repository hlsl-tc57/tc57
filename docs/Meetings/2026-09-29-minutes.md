## 6 Discussions

### 6.1 Normative consensus PRs

The following PRs contributing normative language were approved and the chair merged.

* [Lex.Literal.Vector](https://github.com/hlsl-tc57/tc57/pull/198)
  * Inspired by the content of this PR, Gregory Roth brought up an orthogonal matter regarding re-introducing language enabling creation of 4-element vectors, which as it turned out did not have a related tracking issue. Gregory took an action item to create the issue and add it to the roadmap.
* [Lex.Literal.Char](https://github.com/hlsl-tc57/tc57/pull/199)
  * Chris Bieneman brought to the committee’s attention that the normative addition here matches the DXC implementation and was therefore restricted to UTF-8 Unicode literals.

### 6.2 [Updated Implementation States](https://github.com/hlsl-tc57/tc57/pull/211)

Several proposals have been updated to provide up-to-date links regarding the progress on implementation of each. In merging this PR before generation of the next monthly report, the report will reflect more accurately the committee’s progress.

### 6.3 [\[Math.ConversionFunctions\] Fix incorrect escaping - \#208](https://github.com/hlsl-tc57/tc57/pull/208)

This PR fixes a rendering issue showing double escaped underscores and includes no normative changes.

### 6.4 [\[0006\] Fix missing language about inferring array bound](https://github.com/hlsl-tc57/tc57/pull/209)

This is a pull request to provide further information regarding declaring an array bound. Specifically, that a declaration declaring an array with a bound allows for the omission of the bound on a subsequent definition.

### 6.5 UINT in [proposal 0019 - size type](https://github.com/hlsl-tc57/tc57/blob/main/proposals/0019-size-type.md)

**Jesse Barker** (Invited Expert, Unity) inquired why UINT is treated differently in the list of sized types, leading to a discussion of uint not being a keyword. There is a [tracking issue](https://github.com/hlsl-tc57/tc57/issues/164) in Lex.Keywords. This was discussed at greater length in the [04 August meeting](https://github.com/hlsl-tc57/tc57/blob/main/docs/Meetings/2026-08-04-minutes.md#65-keywords-defect-hlsl-tc57tc57164).

### 6.6 [HLSL Strings (#200)](https://github.com/hlsl-tc57/tc57/issues/200)

**Keith Stockdale** (Microsoft) followed up on any further discussion of HLSL strings. Chris Bieneman recapped the existing issue, and the committee reached consensus to treat string definition as a defect instead of putting it through the proposal process, and that the strawman solution in [\#200](https://github.com/hlsl-tc57/tc57/issues/200) is the preferred solution.
